## 5. Cross-Phase & Architecture Assessment

### 5.1 Architectural Layering & Seam Fidelity
- **`src/domain/` Purity:** Contains zero runtime dependencies on `@forge/*`, React, DOM, or Node I/O. Every pure rule (`deck.ts`, `scoring.ts`, `session-view.ts`, `jira-fields.ts`, `types.ts`) is deterministic and directly reused by Phase 2 backend resolvers without duplication.
- **Hexagonal Dependency Injection (`src/`):** `createSessionStore`, `createRealtimePublisher`, `createJiraClient`, `createBackendLogger`, and `createPokerResolvers` accept narrow port interfaces (`KvsPort`, `RealtimePort`, `JiraRequesterPort`, `LogSink`), while `src/index.ts` serves as the sole production composition root binding `@forge/kvs`, `@forge/realtime`, `@forge/api`, and `@forge/resolver`.
- **Frontend/Backend Boundary (`static/panel/src/`):** All imports from `../../../src/domain/types` in `static/panel/src/` use TypeScript `import type`, ensuring Vite erases cross-boundary imports at compile time and bundles zero backend code into `static/panel/build/`.

### 5.2 Security & Trust Boundaries
- **Host Context Authority (`R2`):** `extractAuthenticatedContext` reads `issueId` and `accountId` exclusively from Forge's host-verified `req.context`, rejecting missing/malformed identifiers via `SAFE_IDENTIFIER_PATTERN` (`^[A-Za-z0-9:._-]{1,128}$`) before any KVS or Jira call and ignoring spoofed payload properties.
- **Vote Secrecy (`R5`):** `projectSessionSnapshot` strips peer card values (`card: null`) while `state === 'voting'`, and `createRealtimePublisher` emits strictly `{ type: 'SESSION_UPDATED', issueId, roundId, reason, updatedAt }` with zero vote values, display names, or account IDs.
- **User-Attributed Authorization (`R10`, `R11`):** `createJiraClient` invokes `api.asUser().requestJira(...)` exclusively (`api.asApp()` is absent from production code) and constructs paths with `@forge/api`'s `route` tagged template after identifier validation.
- **Zero Egress (`R14`):** No `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `navigator.sendBeacon`, external asset URLs, or `permissions.external` entries exist anywhere in the codebase.

### 5.3 Concurrency, Resilience & Operability
- **KVS Concurrency & Pagination (`R4`):** Votes live in isolated per-voter keys (`poker:${issueId}:${roundId}:vote:${accountId}`). Deterministic `nextRoundId(meta)` (`1` on first round, `meta.roundId + 1` on expired round) ensures simultaneous voters opening a fresh/expired round converge on the same `roundId` without clobbering peer votes. Cursor loops (`limit(100)` + `nextCursor`) handle >100 voters cleanly.
- **UI Concurrency & Refresh Deduplication (`R12`):** `ScrumPokerApp` increments `mutationEpochRef` on every local mutation so in-flight background `getSession` responses initiated before a mutation cannot overwrite newer state, tracks `latestFetchIdRef` across concurrent background fetches, and tracks up to 64 applied round IDs (`handledPointsAppliedRoundIdsRef`) so `view.refresh()` runs at most once per saved round even when both the `applyStoryPoints` RPC result and the `'points-applied'` realtime broadcast arrive.
- **Structured Logging (`R14`):** `createBackendLogger` emits structured JSON lines containing safe operational fields while recursively redacting sensitive keys (`card`, `vote`, `votes`, `email`, `emailAddress`, `token`, `authorization`, `secret`, `cookie`), handling circular references and non-plain objects safely.
